# 🟡 Stock Movement Baseline Predictor

A beginner-friendly machine learning project designed to explore the severe challenges, limits, and mathematical hazards of applying classical ML algorithms to highly chaotic financial time-series data.

This project focuses on understanding:

* how sequence lag features are engineered from raw pricing data
* the catastrophic dangers of **look-ahead bias** and data leakage
* why financial data exhibits an extremely low signal-to-noise ratio
* how to analyze class distribution issues when a model takes the "easy way out"

# 📚 What This Project Teaches

## Core Machine Learning Concepts

### 1. Sequential Train/Test Splitting (No Shuffling!)

In ordinary classification projects (like identifying Iris flowers or customer churn), we randomly shuffle rows. In time-series forecasting, **shuffling is strictly forbidden**.

If you randomly shuffle time-series data, your model will train on data from Wednesday to predict what happened on Tuesday. This creates a flaw known as **Data Leakage**, rendering your metrics deceptively high but completely broken in production. We split our data using a strict chronological line:

```text
[   Oldest Data: 80% Training Segment   ] | [ Newest Data: 20% Evaluation Segment ]
=========================================> | ===============>
Past Data Focus                           | Future Simulation (Unseen Data Exam)

```

---

### 2. Feature Engineering for Sequences

Raw historical asset prices are non-stationary and impossible for linear baselines to track directly. We convert nominal pricing data into relative, sequential changes:

* **Daily Return:** Measures instant close-to-close momentum change.
* **Moving Average Tally ($MA_5$ / $MA_{20}$):** Tracks whether today's price is stretched high or low relative to its short and medium-term historical anchors.
* **Rolling Volatility:** Evaluates systemic market fear and variance over a trailing 10-day block.

---

### 3. The Overfitting Baseline Trap

Financial markets approach what mathematicians call an **Efficient Market Hypothesis**. Prices move largely on unpredictable, incoming news shocks, meaning the data contains a staggering amount of noise.

By building a simple, structurally constrained **Logistic Regression** model rather than a complex tree ensemble, we establish a robust behavioral floor. If a complex algorithm claims 75% market prediction accuracy on daily stock directions, it has likely memorized noise, overfit your variables, or leaked future values into its predictors.

# 🏢 The Dataset: S&P 500 ETF (SPY)

Instead of a static CSV file, this script dynamically streams daily market candles from the Yahoo Finance API (`yfinance`).

---

## Engineered Features Used

| Feature | Description | Math Concept |
| --- | --- | --- |
| **Return** | Today's percentage gain or loss | $\frac{\text{Close}_t - \text{Close}_t-1}{\text{Close}_t-1} |
| **MA_5** | Fast trend tracking | $\frac{\text{Close}_t}{\text{Mean of last 5 days}}$ |
| **MA_20** | Medium trend tracking | $\frac{\text{Close}_t}{\text{Mean of last 20 days}}$ |
| **Vol_10** | Market noise / risk gauge | Standard Deviation of the past 10 daily returns |

---

# 🤖 The Model: Logistic Regression

## Idea

Logistic Regression finds a single optimal dividing line that separates days when the stock closed positive from days when it closed down. It provides clean, un-exaggerated feature coefficient scales.

## Understanding the Coefficients (`output/feature_coefficients.png`)

The horizontal bar chart generated by the program displays the exact weights chosen by the model:

* **Positive Weights:** The presence of this signal strongly shifts the model toward predicting an **Up-Market (1)**.
* **Negative Weights:** The presence of this signal shifts the model toward predicting a **Down-Market (0)**.

# Classification Report Analysis

Your model output reveals a classic machine learning phenomenon when dealing with noisy financial data:

### The "All-In" Bias (High Recall, Poor Precision for Down Days)

Look closely at your testing metrics:

* **Recall for Class 1 (Up Days) is 0.99 (99%):** The model guessed "Market is going up" almost every single day.
* **Recall for Class 0 (Down Days) is 0.01 (1%):** The model was completely blind to down days, catching only 1% of them.

### Why did this happen?

The S&P 500 naturally has a strong upward bias over long horizons. In your test set, **58.65%** of the days were up-days. Because financial data is so noisy and hard to read, the Logistic Regression model realized the easiest way to minimize its mathematical loss function was to minimize risk and guess "UP" almost all the time.

# 🚀 Possible Improvements

You can expand this project by applying:

* **Autoregressive Lags:** Explicitly feed the model preceding days' returns (`df['Return'].shift(1)`) so it can spot structural patterns over multiple days.
* **Class Balancing:** Introduce `class_weight="balanced"` to force the model to look closer at down days instead of ignoring them.
* **Walking Validation Windows:** Replace the rigid 80/20 chronological split with a Scikit-Learn `TimeSeriesSplit` cross-validation sequence.
